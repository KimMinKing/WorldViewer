### 공식 문서로 확인한 조건

- Android Gradle Plugin 8.x는 실행에 JDK 17 이상이 필요하고, IDE와 터미널이 같은 JDK를 쓰도록 맞추는 것이 권장된다. 현재 JDK 21이 선택할 AGP/Gradle 조합과 호환되는지는 프로젝트 버전을 정한 뒤 다시 확인한다: [Android 빌드의 Java 버전](https://developer.android.com/build/jdks)
- 실제 기기 실행에는 휴대폰 개발자 옵션과 USB 디버깅, 연결 승인, Windows에서 필요할 경우 OEM USB 드라이버가 필요하다. Android 11 이상은 같은 네트워크에서 무선 디버깅도 가능하다: [하드웨어 기기에서 앱 실행](https://developer.android.com/studio/run/device)
- SDK 패키지는 Android Studio SDK Manager 또는 Command-line Tools로 관리한다. 현재 설치에는 Command-line Tools가 없으므로 CLI에서 패키지 추가·라이선스 점검이 필요하면 먼저 설치해야 한다: [SDK 명령줄 도구](https://developer.android.com/tools/sdkmanager)
- 설치된 API 36을 쓰려면 공식 표상 최소 Android Studio 2024.3.1 Patch 1과 AGP 8.9.1이 필요하다. API 36.1은 더 새 IDE/AGP가 필요하므로 첫 셸의 기본값으로 자동 채택하지 않는다: [API별 최소 도구 버전](https://developer.android.com/studio/releases)
- AGP 8.13.2는 Gradle 8.13과 JDK 17 이상을 지원하고 Kotlin 2.3용 R8을 포함한다. 현재 조합은 이 호환표에 맞춰 고정했다: [AGP 8.13 릴리스 노트](https://developer.android.com/build/releases/agp-8-13-0-release-notes)
- 2026년 8월 31일부터 Google Play 신규 앱과 업데이트는 API 36 이상을 대상으로 해야 하므로 `targetSdk 36`을 사용한다: [Google Play 대상 API 요구사항](https://developer.android.com/google/play/requirements/target-sdk?hl=ko)
- 2026년 개발자 확인 정책과 무관하게 ADB 개발 설치는 등록 없이 가능하다. 공개 배포 조건은 별도 단계에서 다시 확인한다: [Android 개발자 확인 FAQ](https://developer.android.com/developer-verification/guides/faq)

## 아직 확인하지 못한 사항

- USB ADB 전송 실패가 케이블·포트 문제인지 Windows USB 계층 호환 문제인지. 무선 ADB 개발 경로는 정상이다.
- Android Studio 설치 여부가 다른 경로에 있는지와 현재 IntelliJ에서 Android 개발 지원을 쓸 수 있는지.
- 한국어기초사전 전체 내려받기의 실제 파일 크기와 중국어 소설 표본 역검색 적합도.
- release 유사 빌드의 장시간 성능, 4GB RAM급 기기와 태블릿 결과.

## 실제 기기 실행 경로

1. 휴대폰과 PC를 같은 Wi-Fi에 연결하고 개발자 옵션의 무선 디버깅을 켠다.
2. `adb pair <주소:페어링포트>`와 휴대폰의 일회용 코드로 페어링한다.
3. `adb connect <주소:연결포트>` 후 `adb devices -l`에서 `device` 상태를 확인한다.
4. debug APK를 설치하고 시작·회전·재시작을 확인한다. USB ADB 장애를 해결하기 전까지 기준 기기는 이 경로를 사용한다.

## 미해결 문제

- 영어 선택 기능을 v1 완료 조건에 포함할 시점은 사용자 결정이 필요하다.
- 영구 앱 ID·배포 이름은 공개 배포 준비 전에 확정해야 한다.
- 한국어기초사전은 선택적 보조 자료 후보일 뿐이며 실제 내려받기 크기·오인율은 미확인이다. v1은 사용자 정의 뜻을 기준으로 진행하기로 승인됐다.
- 청사진 파일의 실제 경로와 요청 경로가 다르다. 원본 보존을 위해 현재는 루트 파일을 기준 문서로 연결했다.

### 2026-09-25 — 공급원 중립 조회 계약과 오래된 응답 차단

- 상태: 완료 — 단계 10의 첫 하위 작업 완료
- 변경: 조회 원문, 문서 ID·버전, UTF-16 범위, 앞뒤 문맥과 선택 버전을 전달하고 공급원 ID·버전, 표제어·뜻·품사·읽기, 결과 유형, 출처와 저장 정책을 반환하는 계약을 추가했다. 조회 coordinator는 명시적 요청만 실행하며 새 요청이나 취소 뒤 도착한 결과를 전달하지 않는다. 외부 공급원·데이터·인터넷 권한은 추가하지 않았다.
- 검증: `DictionaryLookupCoordinatorTest` 6개와 `.\gradlew.bat assembleDebug test lint`가 성공했다. debug/release 각각 123개 테스트가 실패·오류·건너뜀 없이 통과했고 lint 오류 0건이었다. 요청 전 공급원 호출 0회, 늦은 A 응답 거부, 대기 작업 취소, 결과 없음 정상 처리, 요청·응답 원문 불일치 거부와 캐시 만료 정책을 확인했다. debug APK는 3,331,462바이트다.
- 기기 확인: Galaxy Z Flip4 `SM-F721N`, Android 16/API 36에 debug APK를 설치했고 `MainActivity` 콜드 스타트와 앱 프로세스 실행, crash 로그가 비어 있음을 확인했다. 이 하위 작업은 아직 UI나 실제 공급원에 연결하지 않아 사전 결과 화면은 검증 대상이 아니다. 기존 원본·읽기 위치를 유지했고 새 외부 캐시나 사용자 데이터 파일은 만들지 않았다.
- 미해결: timeout과 공급원별 attribution/cache 적용은 실제 공급원이 정해져야 완성할 수 있다. 한국어기초사전 전체 자료는 신청 전 실제 용량을 알 수 없고 중국어 원어 역검색 오인율도 아직 표본 평가가 필요하다.
- 다음 작업: 한국어기초사전 전체 자료의 신청·재배포 조건과 실제 제공 형식을 확인하고, 확보 가능한 합법적 표본으로 중국어 소설 용어 역검색 적합성을 측정한다.

### 2026-09-25 — 사용자 뜻과 주석 단계 완료

- 상태: 완료 — 단계 9 전체 완료
- 변경: 독서 도구 메뉴에서 내 단어장, 현재 위치 책갈피와 주석 목록을 열 수 있다. 선택 구간에는 강조 또는 메모를 추가하고, 목록에서 원문 위치로 이동하거나 메모를 수정하고 항목을 삭제할 수 있다. 강조는 원문과 병음 레이아웃을 바꾸지 않고 텍스트 배경 계층으로 그린다. 비동기 뜻 요청은 선택 버전을 캡처해 이후 선택이 달라지면 늦게 도착한 결과를 버린다.
- 검증: `.\gradlew.bat assembleDebug test lint`가 성공했다. debug/release 각각 117개 테스트가 실패·오류·건너뜀 없이 통과했고 lint 오류 0건이었다. 선택 A 요청 뒤 B로 바뀐 경우 A 결과를 거부하고 B만 허용하는 테스트를 추가했다. 사용자 뜻 100,000개 색인 생성은 JVM에서 22.30ms, 10,000회 조회는 27.18ms였다. debug APK는 3,331,404바이트다.
- 기기 확인: Galaxy Z Flip4 `SM-F721N`, Android 16/API 36 debug 빌드에서 책갈피 추가와 목록 이동, 선택 강조 추가와 재시작 복원, 메모 추가와 목록 표시, 강조 삭제를 확인했다. 병음 표시 상태에서 가로·세로 회전 후에도 앱이 정상 동작했다. 텍스트 인덱스 캐시를 삭제하고 다시 실행했을 때 캐시는 재생성되고 주석 파일은 유지됐다. 최종 APK를 다시 설치해 콜드 스타트했고 crash 로그는 비어 있었다. 시험 뜻·주석은 제거했으며 원본·현재 문서 메타데이터·읽기 위치 SHA-256은 작업 전 값과 같았다.
- 미해결: 메모 수정 경로는 저장소 자동 테스트와 UI 구현까지 확인했지만 실제 기기에서 키보드로 수정하는 수동 검증은 하지 않았다. 큰 시스템 글꼴·TalkBack에서 늘어난 도구 버튼의 최종 배치, 50MiB 문서의 장시간 주석·검색 사용, 사용자 뜻 100,000개 저장 자체의 지연은 아직 확인하지 않았다. 저장 형식은 첫 버전이라 이전 스키마 마이그레이션 입력이 없다.
- 다음 작업: 단계 10에 들어가기 전에 한국어기초사전 전체 자료를 신청·번들할지, 사용자 정의 뜻만 유지할지 결정하고 실제 자료 크기·라이선스 표시·중국어 소설 표본 역검색 기준을 확정한다.

### 2026-09-25 — 책갈피·강조·메모 저장 형식

- 상태: 완료 — 단계 9의 주석 저장 기반 완료
- 변경: 책갈피·강조·메모를 문서 SHA-256, UTF-16 반열림 구간, 앞/선택/뒤 원문 인용문, 메모와 생성·수정 시각으로 저장하는 버전 1 형식을 추가했다. 책갈피는 한 지점, 강조·메모는 비어 있지 않은 구간만 허용하며 주석 종류에 맞지 않는 payload를 거부한다. 파일은 캐시 밖에 두고 동기화한 임시 파일을 원자적으로 교체한다.
- 검증: `UserAnnotationStoreTest` 4개와 `.\gradlew.bat assembleDebug test lint`가 성공했다. debug/release 각 116개 테스트가 통과했고 lint 오류 0건(기존 Gradle 버전 경고 1건)이었다. 세 종류 왕복, 잘못된 payload·중복 ID 거부, 쓰기 실패 때 기존 데이터 보존과 부분 파일 정리를 확인했다.
- 기기 확인: 저장 형식만 추가한 하위 작업이라 새 주석 파일을 기기에 만들지 않았다. 직전 사용자 뜻 UI 검증 뒤 원본·읽기 위치를 유지하고 시험 뜻 파일은 제거했다.
- 미해결: 새 형식은 문서 해시가 같은 불변 원문에서 오프셋을 그대로 사용한다. 앞으로 원문 버전 간 주석 이관을 지원하려면 인용문 기반 재배치 정책이 별도로 필요하다.
- 다음 작업: 실제 화면에서 현재 위치 책갈피와 선택 구간 강조·메모를 추가하고 목록에서 이동·수정·삭제하게 한다.
